# Browser trial trading removal · 2026-10-15

The user requested removal of the manual paper-trading feature from connected Agent accounts and asked whether the 15-second market-list filter also affects automatic trading.

Removed browser trial buys, the market/amount modal, manual paper sells and their click handlers. Holdings, balances, history, account controls and Agent-authenticated trading remain. The authenticated Owner `/api/demo/trade` POST endpoint is removed too, so an old cached page cannot still submit a trial order. Existing orders and fills are not rewritten or replayed. Updated the bilingual account explanation and versioned assets.

The 15-second condition is an age limit for the last verified market quote, not token age. The removed picker reads `/api/markets` once, filters verified BSC quotes younger than 15 seconds and limits the output to 50; it is not an all-market selector. Built-in Agents independently use `ShowcaseAgents.freshMarkets()` with the same quote-age boundary (up to 24). The pre-release VPS orchestration normally budgets two candidate refreshes per ordinary round (held tokens may add more), while a permitted priority decision explicitly refreshes one token. With discovery, risk, positions/exits and slow inference sharing scheduled work, only a small subset can fall inside the short window at a given moment. This genuinely restricts the built-in AI comparison set; removing the picker does not fix candidate breadth or prove that any missed token would have been bought or profitable.

External Agent trading does not consult that browser picker or its 50-item list. Its own runtime selects and submits a CA, but the platform still requires an active supported BSC Meme candidate, current risk evidence, exact buy/reverse quotes, balance/fees and later-block matching. Removing the picker is not permission to trade arbitrary uncollected tokens.

A reproducible starvation bug was also found: the ordinary self-hosted refresh deducted held tokens and the busiest launch from the two nominal slots. Two held tokens plus a busy launch left zero exploration slots on every round. At 06:26:30Z the actual server lastBatch contained two held-token prices and an unavailable active launch; its exploration cursor had not advanced. The refresh now reserves at least one actual exploration read and places it with the busiest launch in the first parallel batch, then continues held-token refreshes. The separate held-exit priority path, concurrency of two, eight-job bound, 128-request VPS budget, Cloudflare scheduling and service cooldowns are preserved. A six-entry workload with two held tokens visits all six entries across five ordinary rounds; the old algorithm never visited the five non-priority entries. Prices are actually read and risk permission is never manufactured.

All actual freshness, risk and execution requirements, the candidate-pool bound, 30% new-order paper slippage and AI-selected sizing remain. This fixes exploration starvation, not full-market coverage or simultaneous freshness of every discovered coin. Prioritized decision rounds may still refresh a single permitted token and unsupported/blocked routes remain unavailable. It cannot prove any missed token would have been bought or profitable.

Validation: 111 product checks, 145 Cloudflare checks and six VPS checks passed. An authenticated old-page POST for both buy/sell returns 404 without a request/order/account mutation; the same paired Agent can still submit a normal queued paper buy in an isolated fixture. The existing bilingual account projection now exercises a held position while confirming the removed actions are absent. Core formatting, script syntax, VPS build and Worker dry run passed. Live deployment evidence follows after rollout; no production test trade is required.
