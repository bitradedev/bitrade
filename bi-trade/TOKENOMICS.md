# BI 交易费与回购销毁方案

状态：产品设计稿，2026-10-10。实盘依旧关闭；没有部署收费合约、归集资金、执行回购或销毁。此稿不设定未讨论的代币总量与分配。

## 钱包与账户

用户连接的个人 EVM 钱包是 Owner 身份，用于签名登录、管理 Agent，以及未来授权资金操作。每个 Agent 注册时获得独立、永久的 BSC 钱包；Agent 的访问凭据仅控制该 Agent，Owner 能暂停或重连。

当前支持注入式 EVM 钱包，例如安装钱包扩展的浏览器或钱包内置浏览器。尚未接入 WalletConnect 扫码连接。模拟账户可先体验，连接个人钱包的入口应持续可见。Agent 钱包的私钥在服务端加密保存，属于平台管理钱包模式；不能宣传为平台无法接触私钥的完全非托管钱包。

模拟账户的 1000U 是虚拟本金，实际 Agent 地址初始没有这些真钱。登录签名不会转账或创建代币授权。真钱操作仍保持全局禁用。

## 收费口径

采用用户提出的 0.5% 平台交易服务费（50 bps）。设计假设：每次买入和卖出分别收费，收费对象为经平台收费执行路径完成的实盘兑换；不是只对利润收费，也不是对所有钱包转账收费。

| 操作 | 服务费基数 | 0.5% 服务费 |
| --- | --- | --- |
| 买入 | 实际用于本次兑换的 BNB 投入预算 | 从预算中划出，剩余 99.5% 用于兑换 |
| 卖出 | 实际收到的 BNB 兑换产出 | 从实际产出划出，净额返回 Agent |
| 部分成交 | 实际完成的兑换部分 | 只对完成部分计费，退款部分不收费 |
| 失败或回滚 | 无已完成兑换 | 不收服务费，已发生的链上 Gas 仍为实际成本 |
| 登录、配对、授权、充值、提现、恢复 | 无兑换 | 不收交易服务费 |
| 模拟交易 | 虚拟记录 | 不归集真钱；收费规则上线前应用于可区分版本的虚拟成本，不能回写旧成交 |
| 回购 BI | 平台回购任务 | 不再对自身回购收取此服务费 |

例如用户拿 100U 等值 BNB 买入，平台服务费为 0.5U，99.5U 等值 BNB 进入兑换，另付实际 Gas。若随后卖出收到 100U 等值 BNB 的兑换产出，另收 0.5U，返回 99.5U；收益不能忽略两次服务费。DEX 费用、目标代币税费、滑点和 Gas 分开说明，不包含在平台 0.5% 服务费中。

## 费用归集到回购销毁

全部 0.5% 服务费收入进入独立的 BSC 回购金库，以实际收到的 BNB/WBNB 记账。资金先累计，再在流动性与最低可接受产出满足条件时，分批在市场买入 BI，随后销毁买到的 BI；不是直接把收到的 BNB 当作已销毁 BI。

按“全部收入用于回购销毁”的设计，AI、RPC、日常运维及回购 Gas 由平台独立运营预算承担，不能在对外声称 100% 回购的同时暗扣这些支出。若后续改为净收入回购，需要重新明确比例和扣除项。

回购任务使用最大预算、最低 BI 产出、到期时间与分批执行约束；资金不足或报价不合格就保留在金库等待，不承诺固定价格、收益或每个周期一定成交。频繁交易不自动代表可持续收入，平台自己的模拟成交不计入收入与回购金额。

若 BI 合约支持销毁，由回购金库调用 burn，核对链上交易与总供应量变化。单纯转到一个地址，不应显示为已减少合约 totalSupply。ERC20Burnable 的 burn/burnFrom 行为可参考 [OpenZeppelin 官方文档](https://docs.openzeppelin.com/contracts/5.x/api/token/erc20#ERC20Burnable)。具体销毁方式须在 BI 合约确定后落地。

## 公开核对

未来公开页面应分别展示：累计已确认服务费、金库当前余额、累计实际回购支出、累计买入 BI 数量、累计已确认销毁数量，以及对应链上交易。计划、待确认和失败任务不计入已完成金额；区块重组须撤回失效确认。

用户每笔订单展示买卖总额、平台服务费、其他已知费用、净到账和回执。模拟与实盘排行榜应按扣除全部已知成本后的盈亏计算；不能把手续费归集、充值或提现当成交易利润。

## 执行边界与待实现部分

现有 API 允许余额模式 Agent 提交通用合约调用。只在 buy_token 中添加扣费会被其他调用路径绕过，不能据此声称全部实盘买卖必收 0.5%。正式收费需要统一、可核对的收费执行路径，覆盖买入、卖出和所有平台支持的路由；未经解码和核价的通用交换调用不能作为已收费成交。

可使用独立收费执行合约，在一次交易内处理兑换、按实际余额变化计费、返还 Agent 净额并发出费用事件。收款人与最低净产出必须写入订单，避免额外费用后仍按扣费前产出承诺用户。支持转账税币时按实际收到数量计算，不能仅按路由理论输出计算；PancakeSwap 的相关接口见 [Router V2 官方文档](https://developer.pancakeswap.finance/contracts/v2/router-v2)。

用户恢复私钥后自行绕过平台交易的行为不属于平台收费路径，不能保证收取服务费。若要求所有钱包交换都强制收费，需要另行改变账户/执行合约设计和权限模型，不能继续允许任意通用交易同时宣称费用不可绕过。

当前缺少 BI 正式合约、回购市场、收费执行合约、金库与权限配置；因此不启用收费或回购。总供应量、团队分配、流动性投入与解锁计划另行确定，交易费方案不替代这些发行参数。
